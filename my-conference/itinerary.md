# Proposed learning path

This shareable example favors reliable production tools and workers, type-driven
APIs, infrastructure, and robotics. Barcelona local time applies. Availability,
bookings, equipment, and prerequisite readiness must be checked individually.

| Day | Focus | Candidates and tradeoffs |
| --- | --- | --- |
| October 14 | Workshop | Async observability for production diagnostics; robotics or embedded Rust as alternatives. Choose one, confirm registration, and check whether it has already started. |
| October 15 | Contracts and worker design | Compile-time capabilities; unmanned systems or gccrs; trait solver; query systems; language servers or HID; background tasks; type-system direction or hypervisors. |
| October 16 | Failure handling and infrastructure | Streaming state machines; supply-chain security; build systems; atomics; infrastructure compilation or telemetry; standard traits; profiling; build tooling. |
| October 17 | Apply a lesson | Conditional impl Day: explore a small validated tool/worker API, its failure behavior, and observability. |

Keep lunch and coffee breaks and leave venue-transfer time. Alternatives in a
slot are mutually exclusive. A recording is a fallback only when one is actually
published. Use the [official schedule](https://eurorust.eu/schedule/) for exact
titles, times, session pages, and updates.

Capture one question before each session and one concrete follow-up afterward.
Post-attendance findings will be labeled separately from this preparation.
