## Try an example

These fictional profiles show how interests and availability affect choices.
Each JSON itinerary names its snapshot.

| Interest | Focus | Reusable files |
| --- | --- | --- |
| Backend services | Workers, async behavior, production failures | [Profile](backend-profile.json) · [Itinerary](backend-itinerary.json) |

Give your agent an example and the [conference pack](../../exports/conference-pack.md),
then adapt it to your goals. See the [agent guide](../../docs/agent-guide.md) or
the [optional helper walkthrough](../../docs/quickstart.md).

These drafts use topic matches. Confirm prerequisites, access, and bookings.
Keep personal logistics in your own files.

## Share a useful path

Name the audience, author, goals, and availability assumptions. Include choices,
reasons, alternatives, official links, session IDs, and snapshot ID.

Markdown is welcome. For JSON, follow the itinerary schema; maintainers can help
check it. After a source change, review choices and regenerate structured examples
against the intended snapshot.

[Contribute a path](../../CONTRIBUTING.md#where-to-contribute) or
[propose one in an issue](https://github.com/hghalebi/eurorust-2026/issues/new/choose).
