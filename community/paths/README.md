# Find a path that fits your goals

Start with [the owner's written itinerary](../../my-conference/itinerary.md) to
see choices, reasons, and alternatives together. To make your own, copy the
[itinerary template](../../templates/itinerary.md) into your notes and use the
[planning guide](../../docs/planning-guide.md).

## Examples for different interests

These three fictional participant profiles illustrate how goals and available
time can lead to different choices. Their JSON files are reusable inputs and
outputs for an agent or local tool; each itinerary identifies its dataset version.

| Interest | Focus | Reusable data |
| --- | --- | --- |
| Backend services and async reliability | Workers, async behavior, and production failure handling | [Profile](backend-profile.json) · [Itinerary](backend-itinerary.json) |
| Embedded systems and robotics | Hardware interfaces, embedded Rust, and autonomous systems | [Profile](embedded-profile.json) · [Itinerary](embedded-itinerary.json) |
| Rust foundations and API design | Type systems, traits, and API contracts | [Profile](foundations-profile.json) · [Itinerary](foundations-itinerary.json) |

Ask your agent to explain an example using the [conference pack](../../exports/conference-pack.md),
then adapt it to your goals. The [agent guide](../../docs/agent-guide.md) shows
what to supply. If you prefer the local helper, the
[optional walkthrough](../../docs/quickstart.md) produces a Markdown copy.

The examples are starting points generated from topic matches. Confirm
prerequisites, session access, and bookings before attending. Keep your real
personal logistics in your own files.

## Share a path someone else can use

A written plan is welcome: name the audience, author, learning goals, and
availability assumptions, then list choices with reasons and alternatives.
Include official links, session IDs, and the dataset version you used.

Use Markdown for a readable path. For a JSON itinerary, follow the schema and
ask maintainers to help check it if you do not use the local tools. When the
source version changes, review the choices and regenerate structured examples
against the intended snapshot.

[Contribute your path](../../CONTRIBUTING.md#where-to-contribute) or
[propose one in an issue](https://github.com/hghalebi/eurorust-2026/issues/new/choose).
