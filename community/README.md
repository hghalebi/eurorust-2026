## Four paths from a session to a community

### Production agents

[Start with the session reading](../resources/related-talks/talks-lessons-from-building-a-background-task-processing-library.md), then explore [Tokio contributors](../resources/stay-current/communities.md#tokio-contributors), [Rig community](../resources/stay-current/communities.md#rig-community).

**Try:** Read the shutdown resource, then prepare a small example showing what happens to accepted work when a process stops.

**Smaller step:** Read one existing Tokio discussion and record the recovery question it leaves open.

Preparation: Basic async Rust helps; use documentation reading before attempting a runtime change.

Participation routes: [Contribute to Tokio](../resources/stay-current/opportunities.md#contribute-to-tokio); [TokioConf 2027 call for talks](../resources/stay-current/opportunities.md#tokioconf-2027-call-for-talks).

### Types and contracts

[Start with the session reading](../resources/related-talks/talks-what-s-next-for-rust-s-type-system.md), then explore [Rust Types Team](../resources/stay-current/communities.md#rust-types-team), [Rust compiler contributors](../resources/stay-current/communities.md#rust-compiler-contributors), [Exercism Rust](../resources/stay-current/communities.md#exercism-rust).

**Try:** Read one linked source and one Types Team meeting note; separate stable behavior from design proposals.

**Smaller step:** Try one Rust exercise and explain which invalid states its types prevent.

Preparation: Reading a design note is open to newcomers; compiler changes require issue-specific preparation.

Participation routes: [Observe a Types Team discussion](../resources/stay-current/opportunities.md#observe-a-types-team-discussion); [Find a compiler contribution](../resources/stay-current/opportunities.md#find-a-compiler-contribution); [Practise with Exercism feedback](../resources/stay-current/opportunities.md#practise-with-exercism-feedback).

### Infrastructure configuration

[Start with the session reading](../resources/related-talks/talks-your-infrastructure-should-compile-too.md), then explore [Nix and NixOS community](../resources/stay-current/communities.md#nix-and-nixos-community), [Snix](../resources/stay-current/communities.md#snix).

**Try:** Compare the session reading with Snix scope; write down one configuration error that needs a runtime check.

**Smaller step:** Read the project limitations and one related Nix discussion before proposing a change.

Preparation: Nix knowledge helps with implementation. Snix describes unstable APIs and early development.

Participation routes: [Explore a Snix contribution](../resources/stay-current/opportunities.md#explore-a-snix-contribution).

### Robotics and embedded systems

[Start with the session reading](../resources/related-talks/workshops-rust-on-the-field-integrating-real-autonomous-systems.md), then explore [Embedded Working Group](../resources/stay-current/communities.md#embedded-working-group), [Embassy](../resources/stay-current/communities.md#embassy), [Rust bindings for ROS 2](../resources/stay-current/communities.md#rust-bindings-for-ros-2).

**Try:** Read the protocol resource and prepare a question about confirming physical state after a command.

**Smaller step:** Choose a documentation task or read an embedded meeting agenda without buying hardware.

Preparation: Workshop access and async Rust readiness are separate checks; hardware and ROS support depend on the exercise.

Participation routes: [Follow an embedded working-group meeting](../resources/stay-current/opportunities.md#follow-an-embedded-working-group-meeting); [Improve embedded documentation or tooling](../resources/stay-current/opportunities.md#improve-embedded-documentation-or-tooling).

## Make something useful together

Try a reading club, a small experiment, a documentation sprint, a demo, pairing,
or a topic discussion. The [activity template](../templates/community-activity.md)
helps you propose one and record what actually happened. No activity is announced
by this collection.

Start with one source and one question. Share a correction, a reproducible result,
or a useful limitation through the [contribution guide](../CONTRIBUTING.md#communities-and-participation).
Keep private conversations and contact details private.
