# Turn a Rust question into a talk

Start with something you can explain from evidence: a design choice, a useful
failure, a learning problem, or an experiment. Define what the audience should
understand or be able to do afterward.

## From idea to proposal

1. Write the audience, problem, and takeaway in the [proposal template](../../templates/talk-proposal.md).
2. Search [conference history](../conferences/history.md), [topics](../topics/README.md),
   and [speakers’ work](../speakers/README.md). Record what earlier material covers
   and what your experience adds. Similar titles do not prove identical content.
3. Check [calls for talks and workshops](../stay-current/opportunities.md).
   Confirm format, duration, language, eligibility, deadline/timezone, and support
   on the submission page. A closed call can still be a useful example.
4. Draft an abstract with a concrete problem, approach, evidence, and takeaway.
   Describe planned experiments as plans. Follow the event's word limit.
5. Ask for feedback through an available, appropriate route. A public speaker
   profile does not establish that the person offers coaching.

Try the [worked worker-talk proposal](worker-talk-example.md). It is a fictional
exercise connected to existing sources; replace its proposed evidence with your own.

## Prepare the session

| Check | A useful result |
| --- | --- |
| Scope | One question; prerequisites stated; terms introduced before use |
| Evidence | Sources beside claims; measured results include environment and limits |
| Slides | Readable text, described diagrams, meaningful links, and time for pauses |
| Demo | Tested setup, known versions, expected output, and a permitted fallback recording or screenshots |
| Rehearsal | Timed run, feedback, and a shorter ending if time runs out |
| Publication | Agree what may be recorded, captioned, licensed, and linked |

The [RustFest speaker guide](https://rustfesteu.github.io/speakers-guide/)
offers audience and accessibility guidance. Its [remote setup guide](https://rustfest.global/information/speaker-guide/)
is a historical example; confirm current tools and event arrangements separately.

## Teach a workshop

Choose existing exercises from the [course and book library](../library.md#courses-and-books).
The [event practice sources](../library.md#conference-practice) add teaching,
accessibility, and speaker-preparation guidance. Check each work's reuse terms.

Define one achievable outcome and a small successful exercise. Publish the
[readiness checklist](../../templates/workshop-readiness.md): platforms, tested
versions, equipment, expected checks, and a fallback for setup problems.
Say what participants must bring and what the host provides. Describe a setup
as tested only after recording an actual run and environment.

Afterward, link permitted materials from the session record. A published abstract
is not evidence of the original submission or why a committee selected it.
